Concurrent ticket booking service (gRPC)

Engineering · Oct 2025

Engineering · gRPC services

Concurrent clients, no overbooking

A Python gRPC service for booking show tickets, built so that many clients reserving seats at the same time can never oversell a show.

Code on GitHub
  • 3gRPC services
  • Per-showLocks around every reservation
  • StreamingLive seat-availability feed
ServicesThree gRPC services defined in Protocol Buffers. BookingService lists shows, reports seats, reserves and cancels bookings, and streams seat-availability updates. AdminService adds and updates shows, lists bookings, resets data and launches concurrent-booking simulations. LLMService answers user questions.
ConcurrencyEach show has its own re-entrant lock, held while checking availability, decrementing seats and creating the booking, so two clients cannot both take the last seat. Cancellations return seats under the same lock.
TestingAn admin RPC runs many simulated clients at once in a thread pool. Integration tests use it to check, for example, that 10 clients competing for 5 seats confirm at most 5 bookings and never drive availability below zero.
AssistantCommon questions are answered from a small FAQ map; other questions fall back to a Hugging Face sequence-to-sequence model (FLAN-T5 small by default).

Stack

Python, gRPC, Protocol Buffers, pytest, Hugging Face Transformers. Command-line clients for users, admins and the assistant.

Scope

Data is held in memory and payment is mocked; this service runs as a single server.
