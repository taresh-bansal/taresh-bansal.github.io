Fault-tolerant movie-ticket booking on Raft

Distributed Systems course project · Oct – Nov 2025

Engineering · Distributed systems

Bookings that survive a leader failure

A movie-ticket booking system replicated across a 3-node cluster with the Raft consensus protocol, so every node agrees on the bookings and the service keeps running when the leader fails.

Code available on request
  • 3Nodes in the Raft cluster
  • gRPCNode-to-node RPCs
  • RaftLeader election and log replication
  • LocalTransformers FAQ assistant
ProblemA booking service on a single server stops when that server fails, and replicas that disagree can sell the same seat twice. The bookings need one agreed order across machines.
What I built
  • A 3-node cluster whose nodes talk over gRPC, with the Raft messages defined in Protocol Buffers.
  • Leader election with randomized election timeouts and RequestVote RPCs.
  • Log replication of bookings from the leader to the followers through AppendEntries, which also serve as heartbeats.
  • Automatic failover: when the leader fails, the remaining nodes elect a new leader and booking continues.
  • Clients routed to the current leader, and an application server that applies bookings from the replicated log.
  • A local Hugging Face Transformers question-answering model that answers booking FAQs without an external API.

Stack

Python, gRPC, Protocol Buffers, Raft consensus, Hugging Face Transformers.

Completed as a Distributed Systems course project. Code available on request.
