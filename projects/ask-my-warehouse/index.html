Ask My Warehouse

Engineering · Aug – Sep 2026

Engineering · Data and LLM agents

Plain-English questions over a real data warehouse

Ask business questions in plain English and get answers from a real data warehouse, with the SQL shown, role-based access, and human approval for every data change.

How it works

  1. 1PySpark ETLCleans 541,909 raw transactions (UCI Online Retail) with an explicit schema. Duplicates are removed, non-sales rows are quarantined with a reason, and 16 automatic checks stop the pipeline if anything is off.
  2. 2PostgreSQL star schemaOne fact table at invoice-line grain, four dimensions, surrogate keys, an “Unknown customer” row and a full calendar dimension.
  3. 3MCP serverRuns as the logged-in database user and exposes tools per role: discovery, read-only SELECT, CSV export, verified metrics and approval-gated admin fixes.
  4. 4LangChain agentAnswers through the MCP tools only. Gemini first; if a call fails, the same call is retried on a local Ollama model.
  5. 5Web appFastAPI and one HTML page: chat with tables and charts, parallel conversations, and a workbook of pinned answers that refresh straight from the database.

Standard business numbers come from 8 verified metrics assembled from fixed, tested SQL pieces; anything else is labelled as custom SQL and shown to the user. The metrics were checked against independent queries: £9,737,069.01 net revenue and 19,959 orders.

Security in three layers

1. DatabasePostgreSQL roles with column-level grants. Analyst logins are read-only, with a 10-second statement timeout.
2. ToolsThe MCP server offers each role only its own tools; admin tools exist only for the admin role.
3. Human approvalEvery admin change pauses for a human yes or no and is written together with its audit-log row in one transaction. The approval goes into a parameter the AI cannot set, so the AI cannot approve its own change; if no human can be asked, nothing changes.

Known limitations

  • Admin fixes to product names are overwritten when the warehouse is rebuilt; the next step is an overrides table applied by the ETL.
  • Logins are demo values, and conversations are stored as JSON files.
