Behavioral security for LLM-integrated smart cities

Apr 2026

LLM security · Threat modeling

When an LLM's picture of the city stops matching the city

Cities are starting to let LLMs retime traffic signals, route traffic along corridors and answer residents. This work builds one threat model for these systems, names the gap they share, and proposes a framework of defenses for it.

Report: Cognitive-Physical State Integrity: A Behavioral Security Framework for LLM-Integrated Smart City Applications (Apr 2026)

Problem

Smart-city security checks that data arrives intact and from an authenticated sender. Once an LLM sits on the decision path, that is not enough: the model can act on a state that no longer matches physical reality or city policy while every cryptographic and network check still passes. This work calls the missing property Cognitive-Physical State Integrity (CPSI); today no runtime mechanism verifies it. Three failure modes follow.

  • Context integrity violation: falsified telemetry passes authentication and still poisons the model's reasoning.
  • Trust amplification: a low-level exploit, such as a Sybil vehicle cluster, is turned by the model into authoritative, city-scale guidance.
  • Behavioral state divergence: deleted profiles or retired facts can be reconstructed, so the model's behavior drifts from the city's compliance claims.

Architecture

The analysis uses one generalized architecture for LLM integration across three layers of city operations, each grounded in a published or deployed reference system.

Threats

Three classes of threat agent are considered: an infrastructure adversary with network access to weakly governed edge networks; a malicious V2X participant holding valid pseudonymous certificates, software-defined radios or a compromised roadside unit; and a low-privilege or insider user who needs nothing beyond legitimate access to a public or staff interface. Each threat is mapped to CWE and CAPEC, STRIDE and CIA, the OSI layer, MITRE ATT&CK for ICS or ATLAS, and the relevant standard or regulation.

Attack scenarios

Each scenario is traced end to end, from foothold to physical or legal impact.

Signal starvation through MQTT replay

An attacker replays high-occupancy readings into a weakly governed MQTT broker. The occupancy tool hands the LLM a flat sentence with no signature or timestamp; the model extends one green phase and justifies it fluently, and the cross street starves, delaying emergency vehicles.

Corridor misrouting through a Sybil cluster

Using valid pseudonymous certificates, an attacker broadcasts dozens of forged safety messages reporting a hazard. The roadside unit summarizes them as an incident reported by many vehicles, and the corridor LLM turns the summary into urgent rerouting advice that pushes traffic onto residential streets.

Erasure failure through shadow profiling

A resident's health label has been deleted on request, but the surrounding behavioral record has not been masked. Probing the public concierge about transit and parking patterns lets the model infer the deleted status and quietly bias its answers: a privacy violation without any database breach.

Proposed framework

The proposal moves the security stack from checking messages to checking the model's behavioral state, with one mechanism per layer.

1. Provenance-aware tool APIs

Tools that fetch telemetry return signed metadata, freshness and source confidence with every value, so the prompt reads, for example, “occupancy 0.95; confidence low; unverified legacy source; stale”, and the model is conditioned to act on those constraints rather than on the bare number.

2. Uncertainty-annotated aggregation at roadside units

Aggregation keeps spatial and cryptographic conflict markers instead of collapsing them, carrying Sybil suspicion into the prompt so the corridor LLM weighs disputed reports as a skeptical adjudicator rather than amplifying them.

3. Runtime behavioral verification

Post-quantization verification and continuous, automated red-teaming probe the deployed model for knowledge that should be gone, with the goal of showing that erased data cannot be reconstructed from context, as the right to erasure requires.

Scope

This is a threat model and a proposed research framework. It does not include an implementation or experiments, so it reports no measured results.
